# LUTr Camera Transform and Tone-Map Research

LUTr means **LUTrepository**. This audit covers the 13 unresolved camera transforms and five unresolved tone maps present in the catalog on 2026-07-28. Each conclusion is deliberately limited to what the upstream repository, embedded LUT comments, filename, or supplied Nuke graph supports.

## Status summary

| Group | Files | Result |
| --- | ---: | --- |
| ARRI Alexa | 6 | Two upstream-declared transforms; four project-specific CSP exports documented with qualified inferences |
| RED Conversion | 4 | Input and output transfer functions declared; primaries remain unspecified because the LUTs are 1D curves |
| Sony a6000 | 3 | Custom camera input profile and intended emulation/look identified; chromaticities remain unspecified |
| HDR2SDR | 5 | Intended use identified; both formal color-space endpoints remain unresolved because the repository declares no HDR/SDR standard |

“Unresolved” does not mean “creative.” It means that a complete, machine-actionable input/output color-space pair cannot be verified. A LUT can still be a technical transform while declaring only a transfer function, a custom camera profile, or a broad display intent.

## ARRI Alexa LUTs

Upstream: [vfxwiki/ArriAlexaLuts](https://github.com/vfxwiki/ArriAlexaLuts)

ARRI’s own documentation identifies K1S1 as its standard filmic LogC3-to-Rec.709 viewing transform, and explains that a 1D LUT can tone-map the grayscale response but cannot perform the required gamut conversion. The supplied Nuke graph independently labels its matrix “ALEXA wide gamut RGB into ITU Rec. 709.”

### 1. ARRI Alexa V3 K1S1 LogC to Video (1D)

- Evidence: embedded comments say “Alexa conversion LUT, logc2video,” “Full in/full out,” and `alexalutconv (2.09)`.
- Result: input is Alexa V3 LogC / Alexa Wide Gamut; output is the K1S1 video rendering curve while gamut remains Alexa Wide Gamut.
- Limitation: a 1D LUT cannot transform primaries, and the filename does not declare exposure index.
- Catalog action: record LogC3/AWG3 and K1S1 transfer descriptors, keep the complete input/output color-space IDs empty, and warn against treating it as a complete Rec.709 transform.

### 2. ARRI Alexa V3 K1S1 LogC to Rec.709 (3D)

- Evidence: embedded comments explicitly add `itu709`; the Nuke graph uses the same LUT as the direct reference branch; ARRI documentation calls K1S1 the standard LogC-to-Rec.709 transform.
- Result: Alexa V3 LogC / Alexa Wide Gamut to K1S1 Rec.709 video.
- Limitation: the filename does not declare exposure index.
- Catalog action: set output to Rec.709 gamma 2.4, retain qualified LogC3/AWG3 input descriptors, and add an EI warning.

### 3. ARRI LogC to Normal-Primaries Linear — Stage A

- Evidence: the filename is `ArriLogc2NormPrimaryLin_stageA`; the CSP metadata says only “Generated by Foundry::LUT.”
- Result: the name supports LogC/Alexa primaries to linear “normal” primaries, interpreted as Rec.709 primaries in the context of the supplied graph.
- Limitation: the file contains no color-space declaration and is not referenced by the supplied Nuke graph.
- Catalog action: mark the path as inferred from the source label, not source-declared.

### 4. Linear ACEScg to Rec.709 D60 MatchGrade

- Evidence: the filename is `LinAces2rec709A`; the CSP says it was generated by NukeX MatchGrade; the supplied graph explicitly converts ARRI LogC EI400 to ACEScg, then ACEScg to “Output - Rec.709 (D60 sim.),” and labels this LUT “matchGrade Hack.”
- Result: ACEScg input and a project-specific Rec.709 D60-simulation target are supported.
- Limitation: this is not a canonical ACES Output Transform and Rec.709 D60 simulation is not identical to LUTr’s Rec.709 D65 color-space ID.
- Catalog action: set ACEScg input, retain qualified output descriptors without claiming a complete standard output ID.

### 5. Linear ARRI Offset to Rec.709 CMS LUT

- Evidence: the filename is `LinArriOffset2rec709`; the Nuke node is labeled “CMS LUT,” uses ACEScg as its Nuke working space, and the CSP says “Generated by Foundry::LUT.”
- Result: the broad linear-ARRI-with-offset to Rec.709 intent is supported.
- Limitation: neither the offset nor a canonical input encoding is declared; Nuke’s node working space is not itself proof of the LUT’s input endpoint.
- Catalog action: store qualified component descriptors and leave complete color-space IDs empty.

### 6. Linear Normal Primaries to ARRI Rec.709 MatchGrade

- Evidence: the filename is `LinNormalPrimarys2Arrirec709`; the CSP says “Generated by Foundry::NukeX::MatchGrade.”
- Result: the name supports linear normal/Rec.709 primaries to the ARRI Rec.709 rendering.
- Limitation: the file is not referenced by the supplied graph and contains no explicit endpoint declaration.
- Catalog action: mark both endpoints as inferred from the source label and warn that it is a project-specific MatchGrade.

## RED Conversion LUTs

The upstream README explicitly describes these as reverse-engineered transforms from post-debayered REDlogFilm to the corresponding REDgamma viewing curve. The master files are 1024-sample 1D LUTs. A 1D LUT changes channel response but cannot establish or convert RGB primaries, so assigning REDWideGamutRGB would be an unsupported assumption.

## Sony a6000 LUTs

Upstream: [jonmatifa/a6000-LUTs](https://github.com/jonmatifa/a6000-LUTs)

The upstream README declares a custom input: the a6000 Portrait picture profile with contrast, saturation, and sharpness each set to −3. Test footage included a color card, and the output LUTs were generated in DaVinci Resolve. No input/output chromaticities are declared.

- Limitation: the output gamut is not declared, so this is not verified as S-Log2/S-Gamut.
- Catalog action: replace the generic Resolve title and store transfer-level descriptors only.

- Result: custom a6000 Portrait −3/−3/−3 input to an S-Log3 emulation.
- Limitation: the output gamut is not declared, so this is not verified as S-Log3/S-Gamut3.
- Catalog action: replace the generic Resolve title and store transfer-level descriptors only.

### 13. Sony a6000 Portrait −3 to Vivid Look

## Machine-use policy

- Automatic pre-conversion is allowed only when both complete color-space IDs are present.
- Transfer-only or inferred component metadata improves search and human interpretation but must not be promoted to a complete color-space pair.
- “Declared by source” applies to what the source actually declares; it does not fill undeclared primaries.
- Project-specific MatchGrade/CMS exports are labeled as such so users do not mistake them for authoritative ARRI or ACES reference transforms.
